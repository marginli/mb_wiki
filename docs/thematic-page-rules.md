# 主題頁、概念頁、實體頁、綜述頁的規格

> 改編自母庫 `research_with_AI` 的 `EP3/thematic-page-rules.md`。第四節的「判定結果」與第五節的補記是**母庫的歷史紀錄**，頁名都是母庫的頁；本庫只沿用規則本身。本庫 `tags` 的領域值見 `CLAUDE.md`（例：`mb-learning`），不是 `fly-connectome`。

草擬 2026-08-28。對應 EP3。
來源頁（`s-`）的規格在 `ingest-paper` skill 的 `reference/page-spec.md`，本文不重複。
本文只規定另外四種頁型，以及**什麼時候該開一頁**。

---

## 一、四種頁型各自回答什麼問題

| 頁型 | 回答的問題 | 讀者 |
|---|---|---|
| `t-` 主題 | 「這批論文對這件事說了什麼、彼此怎麼對話」 | 想了解一個爭點的人。**index 的第二層** |
| `c-` 概念 | 「這個詞是什麼意思」 | 讀主題頁時卡在術語上的人 |
| `e-` 實體 | 「這個資料庫／工具／結構是什麼、庫內誰用了它」 | 想查一個具體東西的人 |
| `syn-` 綜述 | 「這座知識庫自己現在是什麼狀態」 | 維護者，以及想知道哪些事還沒定案的人 |

判斷 `t-` 與 `c-` 的分界：**如果一句話講得完，它是概念；如果需要講「甲說什麼、乙說什麼、兩者不一樣」，它是主題。**
`c-small-world` 講小世界指數怎麼算；`t-network-organization` 講為什麼同一顆腦
在 LPU 層是小世界、在神經元層有三個社群不是。

## 二、`t-` 主題頁的規格

### 2.1 風格：科普文

**主題頁用科普文的風格寫，不用論文的風格寫。** 這是使用者指定的硬規則。
具體是：

- **白話、直接的敘事。** 依「難題 → 解法 → 代價」推進，不依論文的章節順序，
  也不做「甲篇說 A、乙篇說 B」的逐篇點名式對照——那是索引，不是文章。
- **言簡意賅。** 不寫開場白、不寫「值得注意的是」「有趣的是」這類轉場填充。
  一段話講一件事，講完就進下一段。
- **形容詞只用在客觀的比較與評價上。** 可以寫「精確率約 15%，比召回率低了一個量級」，
  不可以寫「驚人的」「令人震撼的」。這是自用的知識庫，不是流量文。
- **專有名詞首次出現寫「中文（English）」**，與全庫一致。
- **數字要能被驗算**，且必須與 `numbers.md` 一致。

### 2.2 篇幅

**下限 1,500 字，不設上限。** 寫到把爭點講清楚為止。
現有八篇的實測落在 1,600–2,800 字之間。

### 2.3 版面

```markdown
---
title: 中文主題名
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [topic, active, mb-learning]
confidence: high | medium | low
---

# 中文主題名

**一句話寫出這條線在爭什麼。** 獨立一行，粗體。

（導言 2–3 段。用一個具體場景或類比開場，不用定義開場。）

## 小節標題（2–5 個，依論述推進，不依論文順序）

…

## 這條線卡在哪

（收尾。兩件事：最容易被誤讀的一點，以及沒有人處理的缺口。）

## 相關

- [[s-…]] — 這篇在這條線上的位置（一句話）
- 概念：[[c-…]]、[[c-…]]
- 待開頁面：`…`
```

分節線 `---` 只用在 frontmatter 之後，內文不用。

### 2.4 主題頁不做的事

- **不重述來源頁。** 來源頁已經有科普文與專業文；主題頁的價值在於把
  分散在多頁的同一件事接起來。凡是抄得動來源頁一整段的，就表示這一段不該寫。
- **不自己開新的矛盾。** 矛盾在來源頁就地標記、在 `syn-contradictions` 集中。
  主題頁只引用，不裁決。
- **不放圖。** 圖屬於來源頁（有原圖說與解讀四件套）。主題頁需要圖時，用文字轉述並連回該來源頁。

## 三、`c-` / `e-` / `syn-` 的規格

這三種是**參考頁**，不是文章，規格與 `t-` 不同：短、密、可查。

### 3.1 `c-` 概念頁

```markdown
---
title: 中文名（English）
created / updated
tags: [concept, active, <領域或 cross-domain>]
confidence: high | medium | low
---

# 中文名（English）

**一段話的定義。** 不超過三句。

## 怎麼算 / 怎麼判定
（公式或操作型定義。有公式就寫公式。）

## 庫內的用法
| 來源 | 怎麼用 | 得到什麼 |
（一列一篇。這是概念頁的主要價值——同一個詞在不同論文裡的實際用法。）

## 引用時的陷阱
（這個概念在庫內被誤用或容易誤用的地方。沒有就寫「目前無」。）

## 相關
```

字數 400–1,200。**「庫內的用法」那張表是必要的**，沒有它就只是一份維基百科摘要。

### 3.2 `e-` 實體頁

同 `c-`，但小節換成：

```
## 是什麼
## 版本與規模        ← 資料庫類必備，連回 numbers.md
## 庫內誰用了它      ← 表格，一列一篇
## 已知的問題
## 相關
```

字數 300–1,000。

### 3.3 `syn-` 綜述頁

沒有固定骨架，因為它記錄的是狀態而非知識。
唯一的規則是：**每一條都要能被關掉。** 寫下來的每一項矛盾或未解問題，
都要註明「什麼條件下算解決」，否則清單只會愈長。

## 四、什麼時候該開一頁（開頁門檻）

這條規則要解掉 `EP2/source-page-rules.md` 文末的未定案第 3 條
（「只寫 source 頁不夠，但 concept 頁何時開」）。

| 頁型 | 門檻 |
|---|---|
| `t-` 主題 | **至少兩篇來源對它有實質的話要說，而且說的不一樣。** 只有一篇說得到的，留在該來源頁 |
| `c-` 概念 | **至少兩篇來源實際使用它。** 「提到」不算，要「用它算出東西」 |
| `e-` 實體 | **至少兩篇來源引用它，或本庫實際會用到它的資料／程式** |
| `syn-` 綜述 | 有需要集中的跨頁狀態就開，無門檻 |

**兩條配套的但書：**

**1. 工具即主體者不開實體頁。** `e-kaleido`、`e-neuroretriever`、`e-lynsu`
這三個工具各自就是一篇論文的全部內容，開一頁只會複製來源頁。
規則是：**當實體與來源是一對一時，由來源頁承載，不另開實體頁。**

**2. 沒過門檻的不是被拋棄，是被降級。** 未達門檻的概念留在來源頁的
「待開頁面」反引號清單裡，並在相關的主題頁內以一段文字交代。
第二篇來源出現時它就自動過門檻——門檻的作用是排序，不是篩除。

### 4.1 這次的判定結果

| 過門檻 → 開頁 | 未過門檻 → 留在來源頁與主題頁 |
|---|---|
| `c-lpu`、`c-mesoscopic-scale`、`c-neuron-polarity`、`c-community-detection`、`c-small-world`、`c-rich-club`、`c-precision-recall`、`c-segmentation`、`c-standard-brain-registration` | `c-participation-coefficient`（僅 Shih 2019）、`c-hdr-thresholding`（僅 Shih 2021）、`c-hue-ring`／`c-monte-carlo`／`c-visual-distinguishability`（皆僅 Kaleido）、`c-directional-asymmetry`（僅 LYNSU） |
| `e-flycircuit`、`e-standard-brain`、`e-spin`、`e-brain-connectivity-toolbox`、`e-avizo`、`e-mushroom-body` | `e-kaleido`／`e-neuroretriever`／`e-lynsu`（工具即主體）、`e-fast`／`e-yolov7`／`e-3d-unet`（各僅一篇） |

兩處合併的說明：

- `c-modularity`（Shih 2015 提出）與 `c-community-detection`（Shih 2019 提出）
  是同一件事的兩個名字（目標函數與方法），合為 `c-community-detection` 一頁。
- `c-iou`（LYNSU）只有一篇，但它與精確率、召回率是同一類東西
  ——「怎麼替一個預測出來的集合打分」——故併入 `c-precision-recall`，
  該頁因此涵蓋 P / R / F1 / IoU / GS 五個指標，服務三篇論文。

## 五、主題會變動，而且應該變動

八個主題是從**當時的六篇**萃取的，不是果蠅連結體這個領域的完備分類。

> **2026-08-28 補記：** 第二批五篇收錄後，庫內為十一篇。**依本節第 2 條，五篇全部併入既有主題，未新增主題。**
> 本文件其餘內容仍為現行規格。
新來源進來時的處理順序：

1. 先問「它落在哪幾條既有主題上」，把該主題的相關段落改寫。
2. 若它與既有主題都沾不上邊，**先不要開新主題**——一篇論文撐不起一條線。
   把它留在來源頁，等第二篇。
3. 若某條主題底下累積到五篇以上、且內部明顯分岔，才考慮拆分。

**主題頁被拆分或合併時仍適用「不刪頁」的硬規則**：舊頁改標
`tags` 裡的 `superseded` 並註明被誰取代。
