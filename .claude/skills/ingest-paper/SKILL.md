# 攝入一篇論文

把 `papers/` 底下一份 PDF 變成 `wiki/sources/` 的一頁，並更新受影響的其他頁。
庫的位置：本 repo 根目錄（`mb_wiki/`）。

> 本 skill 改編自母庫 `research_with_AI` 的同名 skill。文中提到的 Chiang 2011、Kaleido、LYNSU、natverse 等實例都是**母庫的頁面**，本庫沒有；它們只用來說明每條規則是被哪一次錯誤逼出來的。

**版面規格在 `reference/page-spec.md`——動筆前讀那份，不要憑印象寫。**
`template.md` 是空白骨架，`reference/example.md` 說明既有實例示範了什麼。

---

## 流程

### 0 · 先在登記簿佔位

把 `intake.md` 裡這份 PDF 的狀態改成 `處理中`。**中斷時務必把這個狀態留著**，
否則下次跑 `tools/scan.py` 會把它當成沒動過而整篇重做。

（若這份 PDF 還沒登記過，就新增一列。批次收錄時一次改一篇，不要一開始就全部改成 `處理中`。）

### 1 · 抽取

```bash
./extract.sh "papers/檔名.pdf"
```

產出到 `.cache/<slug>/`：`text.txt`（`-layout` 保留版面）與 `fig-*.jpg`。

**兩件事不能省：**
- **要抽補充資料與方法附錄。** 方法參數多半只在附錄——Chiang 2011 的熱休克時間、
  物鏡 NA、體素大小、七步驟演算法，正文一句都沒有。若 PDF 不含 SM，跟人類要。
- **要看圖，不能只讀文字層。** `pdftotext` 抽不出圖。既有實例有兩個關鍵發現
  只有看原圖才拿得到（逐品系數字、局部註冊的代價）。抽完的圖要**逐張用 Read 看過**。

### 2 · 判斷體裁與收錄範圍

**先問這是什麼體裁**——原著論文／綜述／理論／資料集／專書／預印本。
六節的內容要跟著改，見 `page-spec.md` 的 2.1b。**節數不變，內容改。**

**本庫的範圍是果蠅蘑菇體（mushroom body）的研究**，含其輸入（嗅覺投射神經元等）、輸出（MBON）、調控（多巴胺神經元等）與它支撐的學習記憶行為。
範圍內的子領域不同（分子訊號、電生理、行為、連結體、模型）不另立規則；先問「現有規則哪一條不適用」。
與蘑菇體沾不上邊、或拿不準要不要收時，停下來問人類，**不自行擴充**。

### 3 · 討論，然後停下來

**預設：** 跟人類討論 **3–5 個關鍵發現**，**停下來等回應**，再動筆。

少了這個停點，就變成批次生成一堆沒人讀過的頁面——那只是把 RAG 換成 markdown 存放。
這一步是整個流程裡最容易被跳過、也最不能跳過的一步。

**停下來就是中斷點，所以這一步的筆記要當成交接文件寫。** 對話可能在這裡結束，
下一次恢復的人手上只有 `.cache/<slug>/` 裡那份筆記——**它天生會被當成已核實的事實使用**，
而那正是它的用途（省掉重讀一遍論文）。因此：

- **筆記裡的每一個判斷都標成「待驗證」，不要寫成「已完成」。**
  尤其是否定句（「論文沒有 X」）與從圖上數出來的數目——**那兩類最常被原文推翻**（見寫作紀律第 11 條）。
- **恢復時，逐個否定句、逐張圖回查原文之後才落筆**，不要把筆記的句子直接搬進來源頁。
- **被推翻的項目要寫進 [[syn-changelog]] 的更正清單**（即使它從未發布），
  並在該筆記頂端留一張更正表、註明「不要再引用本檔」。

natverse 那次就是在這一步中斷的，筆記裡有**三項**判斷在動筆時被推翻。
完整規則見庫根 `CLAUDE.md` 的「要更新知識庫時」第 2 步。

**例外：人類明確下了批次指示時**（例如「把這五篇都寫出來」），
不要為每一篇都停下來等回應——那等於要對方確認五次。改為**逐篇回報**：

- 寫完一篇就報一次（新增什麼、稽核出什麼、有哪些矛盾），**然後直接接著寫下一篇**。
- 目的一樣是讓對方能在中途改方向，只是把「事前確認」換成「事後可攔截」。
- **開工前先把這個改動說出來**，不要默默降級——對方要知道你跳過了預設的停點。

**這條例外不放寬矛盾的處理。** 跨來源矛盾仍要就地標 `⚠️ …｜未裁決`、記 log、
在該篇的回報裡點名，**不得為了讓批次跑完而自行圓說法**（見寫作紀律第 4、8 條）。
差別只在於：標記完就繼續寫下一篇，不必停在原地等裁決。

### 4 · 寫 `s-` 頁

依 `reference/page-spec.md`。檔名 `s-姓氏-年份-關鍵字.md`。
圖片複製到庫根 `assets/`，命名 `姓氏年份-figN.jpg`。

**最花工的是每張圖的「解讀」段**——規格第四節列了五條判準，逐條對照著寫。
一句都不要複述圖說。

### 5 · 登記數字

所有具體數字進 `numbers.md`，欄位含「定義／量測方式」與「註記」。
新論文的數字與既有的不同時：**先查定義欄**，多數情況是定義不同而非矛盾。

### 6 · 更新其他頁（不是選項）

只寫 source 頁就收工是錯的。逐項檢查：

- **既有 `t-` 主題頁改寫。** 先問「這篇落在哪幾條既有主題上」，把該主題的相關段落改寫，
  並在該主題的「相關」列出這篇。**一篇論文撐不起一條線——與既有主題都沾不上邊時，
  先留在來源頁等第二篇，不要開新主題。**
- 既有 `e-` / `c-` 頁的「庫內的用法」表補上這篇一列，並檢查「引用時的陷阱」要不要加。
- **新的 `c-` / `e-` 頁要看開頁門檻**（見 `CLAUDE.md` 的「索引與四種非來源頁」）：
  至少兩篇來源**實際使用**才開。未過門檻的留在來源頁的「待開頁面」反引號清單裡。
  這篇可能讓某個原本未過門檻的概念剛好湊到兩篇——**逐一回查其他來源頁的待開清單。**
- 真矛盾就地標 `⚠️ 矛盾`，記 log，回報人類，**並在 `syn-contradictions` 加一條**，
  該條必須寫出「什麼條件下算解決」。
- `syn-contradictions` 的未解問題有沒有被這篇填掉。
- **這篇有沒有推翻先前寫過的東西？有就更正該頁並加更正紀錄，
  同時在 `syn-changelog` 的「本庫更正過自己的地方」加一條。** 這一步最容易被跳過，
  而它正是更新履歷存在的理由。

### 7 · 更新 index、intake 與 log

**`index.md` 的骨架是「領域 → 主題」，不是頁型。** 一篇新來源要動兩個地方：

```
① 它所屬的每一條主題底下的「來源：」那一行
② 文末「全部來源（依發表年）」的總表：- [[頁名]] — 一句話 · YYYY-MM-DD
```

新來源若屬於一個尚不存在的領域，在 index 加一個 H2，並在該頁 `tags` 加上領域值
（例 `tags: [source, active, mb-learning]`）。**不得為此新增 frontmatter 欄位或目錄層。**

`intake.md` 的該列：狀態由 `處理中` 改為 `已收錄`，填上來源頁、領域、日期。

`syn-changelog`：更新「規模的演進」表與「現在的狀態」；**若這一批改變了結構或規則，加一個階段**。

```
log.md     ## [YYYY-MM-DD] ingest | 標題       ← 新的在最上面，只寫做了什麼
```

**收工前跑 `python3 tools/scan.py` 與 `python3 tools/links.py`，兩者都必須乾淨。**

收工前重建靜態網站（內容改了網站才會跟著新；服務常駐，不必重啟）：

```bash
python3 tools/build_site.py            # 有新增圖檔時用完整版
python3 tools/build_site.py --fast     # 只改文字時用這個
```

### 8 · 回報

新增 N 頁、更新 M 頁、K 個矛盾，以及**這篇沒回答到的問題**。

## 寫作紀律

1. **不憑記憶。** 每一句都要能回溯到原文或既有頁面。
2. **`※ 推論`**：論文沒明說的一律標，並寫出依據與不確定範圍。
   推論**不得取代原文**——給了讀法之後仍要寫「但這是我的推論，論文未明說」。
3. **`？待查`**：標了就不要填。既有實例的最大發現，來自堅持標待查而不猜。
4. **⚠️ 矛盾不准當場合併。** 把兩個牴觸的說法圓成通順的一段，
   正好毀掉知識庫最有價值的東西。
5. **數字要能被驗算。** 出現總數就給組成（16,226 ＝ 12,527 ＋ 3,699）。
   同數不同義要點名（「這個 58 與那個 58 互不相干，只是恰好相同」）。
6. **每一節都要有評價，不只有轉述。** 標出證據強度：
   「這是強的定性證據，但樣本為單一神經元類型、n=10」。
7. 繁體中文。術語保留英文，首次出現寫「中文（English）」。
   **翻譯完檢查有沒有英文殘留**（曾出現「四個 family」「三處 give 出」這類漏譯）。

8. **`⚠️ 矛盾` 與「論文自身不一致」是兩類，處理方式不同。**

   | | 例 | 處理 |
   |---|---|---|
   | **跨篇矛盾** | Chiang 2011 說 41 個 LPU，Shih 2015 引用它時說 43 | 標 `⚠️ 矛盾｜…｜未裁決`、記 log、**回報人類等裁決** |
   | **論文自身不一致** | LYNSU 摘要 99.4% vs 結果 99.28% | 標 `⚠️` 記錄即可，**不需人類裁決**——沒有兩個來源要選 |

   前者是本庫要解決的問題，後者是本庫要記錄的事實。混在一起會讓待裁決清單塞滿雜訊。

9. **稽核的固定動作：摘要 vs 正文 vs 圖，三處對照。**
   六篇裡有五篇在這三處之間至少有一處對不上。這是最穩定的發現來源。

10. **不要宣稱唯一性，除非全部讀完。**
    寫第五篇時寫了「本庫唯一 CC BY 的一篇」，第六篇同為 CC BY，只好回頭改。
    「唯一」「首次」「全部」這類字眼，在最後一篇寫完前不要用。

11. **不要寫「論文沒有 X」，除非搜過。**
    這是第 10 條的鏡像：第 10 條管的是對**庫內**的全稱斷言，這一條管的是對**單篇論文**的否定斷言。
    而它更容易錯，因為**稽核的價值幾乎全在這種句子上**——「論文沒報告精確率」「圖說指涉的東西
    圖上沒有」「沒有做統計檢定」，寫對了是本庫最有價值的產出，寫錯了是帶著權威語氣的假發現。

    **落筆前先問「我搜過哪裡」，並實際 `grep` 一次。** 三個已經踩過的坑：

    - **圖說不在你剛才讀的正文裡。** 論文最關鍵的數字可能只印在圖說（實例：natverse 的
      185 候選／178 排除／7 完整重建／7–12 人時，**正文一個字都沒提**）。
      照著章節順序讀正文，會整段跳過圖說。**寫「論文沒給這個數字」之前，先把圖說讀完。**
    - **搜對詞。** 「沒做統計檢定」只要 `grep -i 'p=\|p <\|p >\|test\|significan'` 一次就會被推翻。
    - **否定句錯了，方向常常也一起錯。** 「作者沒做檢定」與「作者做了檢定、得到不顯著，
      卻寫成『兩者相同』」是**相反的兩種批評**，而後者嚴重得多。
      **寫錯不只是不準，是讓讀者錯過真正的問題。**

    **這條規則直接關係到 `page-spec` 3.2 的正確性。** 那一節整節建立在「論文報告了 A 和 B，
    但沒算 f(A, B)」這個句型上——**句型的前半就是一個否定斷言**。那張表每加一列，
    就是多一次寫錯的機會。

    同型的錯有三個尺度，檢查動作相同：
    **「我沒找到」≠「論文沒有」**；**「庫裡沒有」≠「沒有人做過」**；**「我看不出來」≠「圖上沒有」**。
    第三個尺度就是第 3.0 節那個方框（先整頁渲染再指控論文的圖有缺陷）——**同一個錯，換到文字上。**
